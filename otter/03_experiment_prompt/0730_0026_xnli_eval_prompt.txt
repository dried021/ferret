1. 실험 설계 요약 (사용자가 준 원 스펙, 이미 확정된 결론만)
===============================================================================

배경: 공식 XNLI(HF `xnli` dataset, facebook/xnli의 canonical alias)는 15개
언어를 지원하는데, 이 프로젝트의 5개 calibration 언어(EN/KO/ZH/SW/BN) 중
English/Chinese/Swahili만 겹친다. Korean/Bengali는 공식 XNLI에 없다.

확정된 결정:
  - **평가 언어는 en/zh/sw 3개만.** Korean/Bengali calibration checkpoint는
    그대로 평가 대상에 포함하되(그 checkpoint가 en/zh/sw에 주는 transfer/
    interference 효과를 보는 게 목적), 걔네를 위한 "자기 언어" 평가는 하지
    않음. KorNLI/IndicXNLI 같은 대체 데이터셋은 쓰지 않기로 함(번역/annotation
    파이프라인이 달라서 같은 표에 섞으면 안 됨).
  - **Checkpoint 7개**: Original(비압축), English/Korean/Chinese/Swahili/
    Bengali-calibrated(각각 phase1_calib_data.py의 english_only/korean_only/
    chinese_only/swahili_only/bengali_only), Balanced(= mixed_5lang).
  - **6-shot, 전부 English dev에서 고정 선택** (seed=42, label당 2개 =
    entailment/neutral/contradiction 각 2개). 모든 checkpoint·모든 평가
    언어에 동일한 데모 사용 (언어별로 새로 안 뽑음).
  - **Instruction은 영어로 고정**, premise/hypothesis만 평가 언어.
  - **Label mapping 1개만 고정**: A=Entailment, B=Neutral, C=Contradiction
    (XNLI 데이터셋 자체의 ClassLabel 순서 0/1/2와 동일). 3-permutation
    bias-control 체크는 스펙엔 있었지만 "시간 없으면 스킵 가능"한 sanity-
    check 항목이라 이번 구현에는 넣지 않음(§4 참고).
  - **" A"/" B"/" C" 세 continuation의 log-likelihood를 직접 비교**해서
    argmax. 생성(generation) 방식 아님. DeepSeek 토크나이저에서 셋 다 정확히
    1토큰인 것 확인됨(각각 id 338/380/339).
  - **Split**: dev(validation)는 데모 선정에만, test(5,010개/언어)로만
    accuracy 보고.
  - **Metric**: accuracy, delta from baseline, macro avg(3개 언어 단순
    평균), worst-language accuracy, retention %, own-language gain(자기
    언어 calibration이 자기 언어 평가에서 다른 단일언어 calibration들
    평균보다 얼마나 나은가 -- en/zh/sw에 대해서만 정의됨), balanced gap.

(전체 원문 설계는 이 대화 세션 첫 메시지에 있던 15개 섹션짜리 한국어 스펙
-- 위는 "실제 구현에 반영된 확정 사항"만 추림. 원문 전체가 다시 필요하면
사용자에게 재요청할 것, 이 프롬프트 파일엔 안 옮겨 적음.)
