1. 연구 배경과 위치
===============================================================================
(0727_2300판/0729_0900판과 동일, 변경 없음 — 그대로 유지)

D²-MoE는 AWQ/GPTQ 같은 quantization이 아니라, expert weight를 shared base +
expert-specific delta로 분해하고 Fisher-weighted merging / activation-aware SVD
(whitening) / structured pruning(pp_ratio)을 쓰는 training-free MoE 압축 방법이다.
이 프로젝트는 새 압축 알고리즘을 제안하지 않고, calibration corpus의 "언어 구성"이
이 압축 절차(어떤 expert/parameter가 보존되는지)와 압축 후 다국어 성능에 미치는
영향을 체계적으로 검증한다. 단, §6(제안 방법)에서 calibration *sampling 전략*
하나는 제안했으나(압축 알고리즘 자체는 불변), 그 검증 결과는 negative다(§6 참고).

**연구 공백 (선행 연구 대비)**
- Transfer gap: dense PTQ(quantization)에서 확인된 "calibration 언어가 중요하다"는
  결과가 training-free MoE decomposition(D²-MoE)에도 적용되는지 검증한 선행 연구 없음.
- Localization gap: 효과가 있다는 것을 넘어 어느 레이어, 파이프라인의 어느 하위
  단계(Fisher merge/whitening/pruning)에서 발생하는지 짚은 선행 연구 없음.
- Cross-validation gap: forward-only proxy 신호가 실제 gradient 기반 Fisher와
  일치하는지 교차검증한 선행 연구 없음.
- Prescription gap: 진단에서 그치지 않고 같은 calibration 비용 안에서 효과를
  완화하는 구체적 방법을 제안·검증한 선행 연구 없음(■ 본 연구는 이 gap을 시도했으나
  제안한 구체적 방법 하나는 실패했다는 negative result로 채웠다 — §6 참고. gap
  자체가 어렵다는 것을 보이는 것도 기여로 서술 가능).

**[2026-07-27 랩 피드백] novelty 재정의**: "calibration 언어가 압축 결과를
바꾼다"는 효과 자체(Transfer gap)는 dense quantization/pruning 문헌에 이미
보고돼 있어 그것만으로는 본 논문의 기여로 약하다는 지적이 있었음. 본 논문의
핵심 novelty는 **Localization gap**(D²-MoE 파이프라인 단계별 — Fisher 병합/
SVD whitening/structured pruning — 원인 규명)로 재정의한다. Transfer gap
확인(§4.1)은 필요한 전제 확인 단계이지 논문의 핵심 주장이 아니다.

**Fisher-merge only 결과 재확인**: Fisher-merge 단계는 lossless 단위 테스트로
확인 완료(§3.11). whitening 단계도 seed 3개+placebo로 확정됐다(§3.12,
SUPPORTED). pruning 단계는 §3.13(korean_only 단일 조건) ablation으로 확인됨.

**참고/비교 대상 문헌**: D²-MoE(기준), Calibrating Beyond English(dense PTQ
calibration 언어 영향 선행 연구), MoEQuant(expert-balanced calibration 필요성),
MoE-I²/MoBE(§7 일반화, future work로 컷). — 0727_2300판과 동일, 변경 없음.

**본 연구의 기여 요약 (■ 4번 갱신)**
1) D²-MoE 기반 training-free MoE compression에서 calibration language 영향을
   체계적으로 평가한 최초의 다국어 분석.
2) EN-only/target-language/multilingual calibration을 동일 token budget 아래
   비교하고 평균 성능뿐 아니라 worst-language robustness 분석.
3) routing coverage, Fisher importance, whitening activation statistics,
   SVD energy, structured pruning 민감도 분석으로 calibration 언어와
   압축 후 성능의 관계를 단계별로 설명.
4) ■ (검증됨, negative) 불일치(disagreement) expert에 calibration 예산을 표적
   배분하는 calibration sampling 전략을 제안·검증했으나 Balanced를 이기지
   못했다(NOT_SUPPORTED) — 이유는 "라우팅 불일치"가 "압축 후 실제 저하"의
   좋은 프록시가 아니었기 때문임을 원인 분석으로 보였다(§6). 이 자체를
   방법론적 negative result로 논문화할지, §6을 대안(예: 단일언어 self-calibration
   저하량 기반 신호로 교체)으로 재시도할지는 미결정 — 사용자 판단 필요(§8).
"새로운 압축 알고리즘"이나 "SOTA"는 주장하지 않는다.

   현상이 확인되어, merge_eval 단계만은 반드시 GPU 2장을 동시에 확보해 모델
   전체가 VRAM에 완전히 올라간 상태에서 실행하도록 파이프라인을 고정했다.
   Fisher/SVD-scale 단계는 GPU 1장으로 안정적으로 동작한다.
2) 여러 GPU가 서로 다른 조건/seed를 동시에 처리하다 merge_eval 단계에서
   보조 GPU를 공유해야 할 때는 파일 락(flock)으로 직렬화한다.
3) 각 단계는 실패 시 최대 40회, 90초 간격으로 자동 재시도한다.

하이퍼파라미터(delta_ratio=0.8, pp_ratio, calibration 예산 64 samples x
seqlen 512)는 전혀 바뀌지 않았다 — 바뀐 것은 GPU 자원 배분 방식뿐이다.

5. 방법론 상세 (재현성/Methods 섹션용, ■ GPU 절 전면 재작성 — A100 서술 완전 삭제)
===============================================================================

**모델**: Qwen3-30B-A3B(bf16, 48레이어, forward-only 진단 전용, 압축 실험에는
미사용) / deepseek-ai/deepseek-moe-16b-base(bf16 ~31GB, 28레이어: 0번 dense+
1~27 MoE, 64 experts/레이어, 실제 압축 대상). — 변경 없음.

**압축 방법**: 공식 D²-MoE repo(github.com/lliai/D2MoE, Apache-2.0).
Fisher-weighted merge(merge_method="fisher") + SVD delta(delta_ratio=0.8,
실사용 rank=667/full 1408) + whitening(3 seed+placebo로 확정) + structured
pruning(pp_ratio=0.2, korean_only 조건 ablation으로 확정). — 변경 없음.

**Calibration 데이터**: `israel/flores-parallel`(HF, FLORES-200 parallel test
split). 언어 조건: English/Korean/Chinese/Swahili/Bengali(각각 단일언어
100%) + Balanced(mixed_5lang, 5언어 균등 혼합). calibration 예산: 64 samples
x seqlen 512(모든 조건 동일). — 변경 없음.

**평가**: FLORES-200 devtest, 언어당 held-out 60문장, 지표는 bits-per-byte(bpb)의
압축 전 대비 상대 증가율(%). calibration pool은 평가용 앞 60개와 완전 분리. —
변경 없음.

**Seed**: 조건당 3개(0/1/2). ■ english_only/korean_only/chinese_only/
swahili_only/mixed_5lang은 3 seed 전부 완료. bengali_only만 fisher 3 seed
완료, svd_scale/merge_eval 미완료(§3.19).

**Placebo(noise floor) 설계**: 동일 언어의 겹치지 않는 다른 표본으로
calibration한 대조 조건(english_only_b/korean_only_b/swahili_only_b)을 별도로
둔다 — Chinese/Bengali는 예산 우선순위상 placebo 조건을 두지 않았다(원래부터의
설계, 변경 없음). ■ 세 placebo 조건 중 english_only_b/korean_only_b는 3/3,
swahili_only_b는 2/3 완료(seed2 진행 중).

**통계 검정**: Spearman correlation, bootstrap 95% CI, 사전 등록. §4.1은
own-language 판정에 한해 seed 3개가 신뢰구간을 내기엔 적어 **부호 일관성 +
2x noise-floor 여유**를 사전등록 기준으로 쓴다(§3.19 표 참고).

**■ GPU/실행 환경 (전면 재작성, A100/RunPod 서술 전부 제거)**:
- 실행 환경은 처음부터 끝까지 로컬 호스트 하나뿐이다: 공유 4x3090(24GB x4).
  모든 실험(§4.1 grid, §4.3 단계 분리, §6 제안 방법 검증 포함)이 로컬
  4x3090만으로 재현 가능하다.
- Fisher 계산(진짜 gradient)은 레이어별 freeze-and-accumulate 트릭으로 GPU

- **merge_eval(최종 압축+평가)만은 GPU 2장을 동시에 페어링해서 실행한다**

  (NOT_SUPPORTED)** — 무제약 변형은 3/3 seed 패배, cap50 변형은 1/3만 근소
  승리. 원인: Stage 1의 "라우팅 불일치" 프록시가 측정하는 것(이 언어가 이
  전문가에서 calibration 샘플을 충분히 받았는가)과 실제 문제(이 언어가
  압축 후 얼마나 나빠지는가)가 이 실험 조건에서는 상관관계가 약하거나
  반대 방향이었다. 결정적 반증: cap50이 Bengali에 Balanced보다 더 많은
  예산(35%>20%)을 줬는데도 여전히 졌다 — "예산 부족"이 원인이 아니라
  "엉뚱한 expert에 집중했다"는 것을 시사한다. 게다가 Bengali는 단일언어
  100% calibration(이론적 최선)으로도 저하율이 Swahili보다 훨씬 크다
  (Bengali 17.5~17.8% vs Swahili 12.8~13.5%) — Bengali는 예산 배분 전략과
  무관하게 이 압축 파이프라인에 원래 더 취약한 언어로 보인다. 상세 근거는
  `01_plans/06_불일치표적배분_실측결과.md` 전문 참고.

**범위 한정 문구(반드시 지킬 것, 이전판과 동일)**: whitening까지는 "D²-MoE의
Fisher-merge+whitening 경로가 calibration 언어에 민감하다"로 확장해서 쓸 수
있다. pruning까지 포함해 쓰려면 korean_only 조건 하나의 ablation이라는 범위를
명시할 것.

7. 한계 (Limitations 섹션 초안 재료, ■ 갱신 — A100 관련 항목 완전 삭제)
===============================================================================

- 실제 압축 결과는 DeepSeek-MoE-16B 한 아키텍처에 한정 — §7 일반화는 future
  work로 컷.
- calibration과 평가 데이터가 FLORES-200으로 상당 부분 겹쳐 도메인 겹침
  confound 완전 배제 못함.
- Structured pruning 경로는 korean_only 조건 하나의 on/off ablation으로만
  확인됐다 — 전체 grid 검증은 스코프 밖.
- Downstream task(XNLI, MGSM, Belebele 등) 평가 아직 없음.
- 다룬 언어는 EN/KO/ZH/Swahili(완료) + Bengali(진행률 최저, fisher만 완료).
  시간이 더 부족해지면 Bengali를 §4.1 Table 1에서 각주 처리하거나 제외하는
  것을 컷라인으로 고려(§8).
- **■ §6 제안 방법(disagreement-aware calibration)은 확정적으로 실패했다
  (NOT_SUPPORTED, §6 참고). Limitations이 아니라 negative result로서 본문
  §6 자체에서 정직하게 보고할 것 — 숨기거나 "미검증"으로 얼버무리지 말 것.**
- §5(메커니즘) 4갈래 분석 중 ③④(SVD basis rotation, 인과 사슬 검증)가
  여전히 미착수.
- 재현 환경은 로컬 공유 GPU 서버(4x3090) 하나뿐이며, 다른 사용자와 공유하는
  환경이라 실행 시점의 GPU 가용성에 따라 진행 속도가 들쭉날쭉했다 — 이 자체는
  결과의 타당성에 영향 없는 인프라 요인.
