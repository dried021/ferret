> [02_Toy_실험.md](02_Toy_실험.md)에, 현재 상태 한 줄 요약은

> 그리고 통과 이후 어디로 가는지의 전체 지도 역할을 한다.

## 0. 연구 범위와 용어 정리

본 프로젝트는 D²-MoE의 압축 파이프라인에 사용되는 calibration data의 언어 구성이
압축 후 다국어 성능과 expert/routing 통계에 미치는 영향을 분석한다.

중요:
- D²-MoE는 일반적인 AWQ/GPTQ식 "양자화(quantization)" 방법이 아니다.
- D²-MoE는 expert weight를 shared base weight와 expert-specific delta로 분해하고,
  Fisher-weighted merging, activation-aware SVD, structured pruning을 사용하는
  training-free MoE 압축 방법이다.
- 따라서 논문에서는 "multilingual calibration for D²-MoE compression"이라고 쓰는 것이
  정확하다. quantization이라는 표현은 별도 AWQ/GPTQ 실험을 추가할 때만 사용한다.

> **[2026-07-27 v3, 랩 피드백] novelty 재정의:** RQ1~RQ3(calibration
> 언어가 압축 결과를 바꾼다는 관찰) 자체는 dense quantization/pruning
> 문헌에 이미 보고돼 있어 그것만으로는 기여로 약하다. 본 논문의 핵심
> novelty는 **RQ4**(어느 파이프라인 단계 — Fisher merge/whitening SVD/
> structured pruning — 에서, 왜 발생하는가)로 재정의한다. 자세한 근거는
> [06_논문_구성.md](06_논문_구성.md) §1 "novelty 재정의",
> [claude_plan.md](../01_plans/claude_plan.md) v3 참고.

## 1. 잠정 제목

영문:
Does Calibration Language Matter for Compressing Multilingual Mixture-of-Experts Models?

대안:
- Beyond English Calibration for Mixture-of-Experts Compression
- Revisiting Calibration Data in Training-Free MoE Compression
- Multilingual Calibration Effects in D²-MoE

## 2. 연구 목표

새 압축 알고리즘을 제안하지 않고, 다음 질문을 체계적으로 검증한다.

**RQ1.** 영어 calibration data만 사용한 D²-MoE 압축은 비영어 언어의 성능을 더 크게
손상시키는가?

**RQ2.** 평가 언어와 calibration 언어가 일치할 때 압축 후 성능이 개선되는가?

**RQ3.** 여러 언어가 섞인 calibration set이 영어 단일 언어보다 평균 성능과 최악
언어 성능을 안정적으로 개선하는가?

**RQ4.** calibration 언어에 따라 Fisher importance, activation statistics, expert
routing coverage, delta SVD rank allocation이 달라지는가?

**RQ5.** 다국어 calibration의 효과는 압축률이 높아질수록 커지는가?

## 3. 핵심 가설

- **H1.** 영어-only calibration은 영어 평가 성능에는 경쟁력이 있지만, 다국어 평균 및
  worst-language 성능에서는 multilingual calibration보다 불리하다.
- **H2.** 동일 언어 calibration은 해당 언어 평가에서 가장 높은 성능을 보일 가능성이 있다.
- **H3.** 균형 multilingual calibration은 특정 언어에서 항상 최고는 아니더라도,
  macro-average와 worst-language 성능에서 가장 안정적이다.
- **H4.** 언어별 tokenization 및 activation 차이가 Fisher importance와 expert
  activation coverage를 변화시키며, 이것이 압축 후 성능 차이와 상관관계를 가진다.
- **H5.** 낮은 압축률에서는 calibration 언어 차이가 작고, 높은 압축률에서 차이가 커진다.

> Toy0([02_Toy_실험.md](02_Toy_실험.md))은 H4의 전제조건만 떼어낸 것이다 — 압축을 아직
> 돌리지 않고, "calibration 언어를 바꾸면 라우팅/중요도 통계가 실제로 달라지는가"
> 부터 싸게 확인한다.

## 4. 최소 실행 버전(MVP)

논문 사이클 경험이 목표이므로 첫 실험은 아래 범위로 제한한다.

**모델:**
- 1차 권장: Phi-3.5-MoE 또는 DeepSeekMoE-16B-Base 중 실제 실행 가능한 하나
- 2차 확장: Mixtral-8x7B 또는 Qwen2-MoE 계열 하나 추가

주의: 모델이 실질적으로 여러 언어를 지원하는지 FP16/BF16 원본 성능으로 먼저 확인한다.
원본 모델의 특정 언어 성능이 매우 낮다면 calibration 효과 해석이 어려우므로 제외한다.

> 이 저장소에는 이미 Qwen3-30B-A3B가 이 호스트(4x3090)에서 로드/검증되어 있고
> (해당 방향은 중단되어 `archive_failed/ferret_kr`, `archive_failed/ferret_toy0_qwen3_ver1`로
> 옮겨졌다), FLORES-200 기반 다국어 PPL 파이프라인도 있다. Toy0은 새 모델을 받지
> 않고 이 자원을 그대로 재사용한다. Phi-3.5-MoE 등
> MVP 표준 모델 도입 여부는 Toy0 통과 이후 Phase 0에서 별도로 결정한다.

**압축 방법:** D²-MoE 공식 구현, 원 논문의 기본 hyperparameter 우선 사용, 알고리즘
수정 없음.

**압축률:** 40%, 60%

**calibration 조건:** C1. English-only / C2. Korean-only / C3. Chinese-only /
C4. Balanced multilingual

**MVP 언어:** English, Korean, Chinese

**calibration sample 수:** 조건별 동일한 총 token 수. 권장 128 sequences x 512
tokens (예산 부족 시 64 x 512). multilingual 조건은 언어별 token 수를 동일 배분.

**random seed:** 최소 3개 (제한된 예산에서는 pilot 1 seed, 최종 결과는 3 seeds)

**MVP 총 압축 실행 수:** 1 model x 2 compression ratios x 4 calibration settings x
3 seeds = 24 runs (예산 부족 시 1 model x 1 ratio(60%) x 4 settings x 3 seeds = 12 runs)

## 5. 권장 확장 버전

MVP에서 언어 효과가 관찰될 때만 확장한다.

- 모델: 2개 MoE 모델
- 언어: English, Korean, Chinese, Japanese, French 또는 Spanish
- calibration 조건: C1 English-only / C2 Korean-only / C3 Chinese-only /
  C4 Evaluation-language matched / C5 Balanced multilingual /
  C6 Natural-frequency multilingual / C7 Random multilingual (language labels 무시)
- 압축률: 40%, 50%, 60%

확장은 모든 조합을 돌리지 말고, MVP에서 의미 있었던 조건만 선택한다.

## 6. Calibration Dataset 구성

가능한 데이터: Wikipedia 또는 CulturaX/OSCAR 계열의 동일 도메인 다국어 텍스트.
동일한 장르와 전처리를 언어 간 유지하는 것이 중요. 라이선스와 재배포 조건 확인.

권장 통제:
- 모든 언어에서 동일한 sequence length
- 동일한 총 token 수
- 동일한 문서 수 또는 유사한 문서 길이 분포
- 중복 제거
- 평가 benchmark와의 contamination 제거
- 지나치게 짧은 문장 제거
- 코드, 표, URL 비율 통제
- tokenizer 기준 token 수로 맞추고 문자 수로 맞추지 않음

Balanced multilingual 예: 총 65,536 tokens라면 English 21,845 / Korean 21,845 /
Chinese 21,846.

Natural-frequency multilingual: 실제 pretraining 분포는 알기 어려우므로, 명확한
공개 기준이 없으면 부가 실험으로만 사용한다. 주 실험은 balanced mix가 해석하기 쉽다.

## 7. 평가 데이터셋

**A. 언어 모델링 성능**
주 지표: language별 perplexity 또는 normalized log-likelihood.

주의: 서로 다른 언어의 raw perplexity를 직접 평균하면 tokenizer fertility 차이로
왜곡될 수 있다. 다음을 함께 보고한다: 1) 언어별 PPL 2) 원본 모델 대비 상대 PPL
증가율 3) byte-normalized 또는 tokenization-normalized 지표 4) macro-average.

가능한 데이터: FLORES-200 dev/devtest의 문장 likelihood, multilingual Wikipedia
held-out, mC4 held-out, calibration corpus와 겹치지 않는 동일 도메인 테스트셋.

**B. 다국어 downstream**
- MVP: XNLI, PAWS-X, MGSM (영어/한국어/중국어)
- 확장: Belebele, XCOPA, XQuAD 또는 MLQA, multilingual MMLU 계열
- 권장: 생성 태스크 1개 + 분류/선택 태스크 2개. 지나치게 많은 benchmark를 넣지 않는다.
  EACL형 분석 논문에서는 언어별 결과와 원인 분석이 benchmark 개수보다 중요하다.

**C. 효율 지표**
압축 전후 parameter storage, GPU memory peak, 압축률, 가능하면 tokens/sec, 압축
생성 시간, 추가 calibration 시간.

## 8. 비교 조건

필수: B0 Original BF16/FP16 model / B1 D²-MoE + English calibration /
B2 D²-MoE + target-language calibration / B3 D²-MoE + balanced multilingual calibration

권장: B4 D²-MoE + random calibration language mix / B5 D²-MoE 원 논문 기본 calibration 설정

선택적 baseline: 단순 expert merging 또는 pruning baseline 1개. 목적은 D²-MoE
자체의 SOTA 재검증이 아니라 calibration effect 분석이므로 너무 많은 compression
baseline은 필요 없다.

## 9. 통제 변수

아래 항목은 모든 calibration 조건에서 고정한다: 모델 checkpoint, tokenizer,
calibration token budget, sequence length, number of samples, compression ratio,
SVD/pruning hyperparameters, batch size, random seed 목록, evaluation prompts,
few-shot example 수, decoding 설정, hardware, software versions. 언어만 바뀌도록
설계해야 한다.

## 10. 주요 결과 지표

Primary metric: 다국어 downstream macro-average의 원본 대비 성능 보존율.

```
retention(language) = compressed_score(language) / original_score(language)
```

함께 보고할 지표: Macro-average retention, Worst-language retention, English
retention, Non-English average retention, 언어 간 표준편차, 압축률별 성능 감소량,
seed 평균과 표준편차.

권장 핵심 표 — 행: calibration 조건 / 열: EN, KO, ZH, Macro Avg., Non-EN Avg.,
Worst Language, Memory Reduction.

## 11. MoE 특화 분석

이 부분이 단순 재현 실험을 논문다운 분석으로 만든다.

**A. Expert routing coverage** — 전체 expert 중 한 번 이상 활성화된 expert 비율,
expert별 token count, routing entropy, top-k expert frequency, Gini coefficient
또는 coefficient of variation, layer별 expert imbalance.
질문: multilingual calibration이 더 많은 expert를 고르게 방문하는가? 특정 언어가
특정 expert 집합을 선호하는가?

> Toy0은 이 항목 A를 압축 없이, 이 저장소에 이미 있는 routing hook만으로 먼저
> 확인한다.

**B. Calibration-evaluation routing overlap** — 각 calibration 조건 c와 평가 언어
l에 대해 expert usage distribution cosine similarity, Jensen-Shannon divergence,
top-expert overlap. 가설: calibration과 evaluation의 routing distribution이 유사할수록
압축 후 성능이 높다.

**C. Fisher importance shift** — 언어별 Fisher importance 분포, expert별 Fisher 합,
layer별 Fisher 차이, 영어 calibration과 비영어 calibration 간 rank correlation.
질문: 영어-only calibration이 비영어에서 중요한 expert/weight를 낮게 평가하는가?

**D. Activation statistics** — layer별 activation max, percentile(99, 99.9),
variance, outlier ratio, 언어 간 activation range 차이.

**E. Delta SVD 분석** — expert/layer별 retained rank, energy retention, calibration
언어별 effective rank 차이, rank 변화와 downstream degradation의 상관관계.

## 12. 핵심 상관관계 분석

1) routing overlap vs performance retention
2) expert coverage vs macro-average retention
3) Fisher rank correlation vs language-specific retention
4) activation range mismatch vs performance drop
5) retained SVD energy vs performance retention
6) **(추가, 2026-07-25) expert별 Fisher 순위의 언어 간 divergence × 그 expert가
   처리하는 토큰의 언어 분포 × 해당 언어의 성능 저하 기여** — 셋을 함께
   상관시키면 "KO에서 중요한 expert가 EN calibration에서 저평가되어 delta
   rank를 적게 받고 그래서 KO가 무너졌다"는 인과 사슬이 완성된다. 1~5번이
   양 끝(입력-출력) 상관이라면, 이 항목이 그 사이 메커니즘을 채운다 —
   [04_전체요약.md](04_전체요약.md) "다음 단계" 2.5) 참고.

Spearman correlation을 기본으로 사용한다. 표본 수가 작으면 p-value를 과도하게
강조하지 말고 effect size와 scatter plot을 함께 제시한다.

## 13. Ablation

- 필수 1: Calibration token budget (16k / 32k / 64k) — 다국어 효과가 단순히 더
  다양한 샘플 수 때문인지 확인
- 필수 2: Language diversity vs target-language matching (English-only / target-only
  / multilingual-balanced)
- 필수 3: Compression ratio (40% / 60%)
- 선택: 동일 도메인 vs 서로 다른 도메인 다국어, balanced vs skewed mix, sentence-level
  vs document-level mix, Fisher-weighted merge만 언어 변경, activation-aware SVD만
  언어 변경, pruning statistics만 언어 변경 — 마지막 선택 ablation은 D²-MoE의 어느
  단계가 calibration 언어에 민감한지 분리하는 데 유용하다.

> **(추가, 2026-07-25) 위 "마지막 선택 ablation"은 더 이상 선택이 아니라 논문
> 구조상 필수다.** 지금 있는 결과는 입력(calibration 언어)과 출력(KO bpb
> 저하율) 양 끝뿐이고, 그 사이 어느 단계(Fisher-merge/whitening SVD/pruning)가
> 실제로 반응하는지 분리하지 않으면 "왜 그런지 모르는 관찰 논문"으로 읽힌다.
> 비용은 새 실험이 아니라 기존/예정 run에 저장 훅을 추가하는 정도 —
> [04_전체요약.md](04_전체요약.md) "다음 단계" 2.5) 참고.
>
> **(추가, 2026-07-27 v3) 이 ablation이 사실상 논문의 novelty 그 자체다.**
> Fisher-merge/whitening SVD/pruning 세 단계를 분리하는 것이 §4.3의 핵심
> 설계이며, 이걸 뺀 "효과가 있다"만으로는 dense quantization/pruning
> 선행 연구 대비 기여가 성립하지 않는다. 또한 각 단계 결과를 확정하기
> 전에, "delta/정보가 보존되면 그 단계를 바꿔도 원본과 동일해야 한다"는
> 성질을 구현/평가 조건과 함께 재확인하는 것을 원칙으로 한다(Fisher-merge
> 단계는 이미 lossless 단위 테스트로 1차 확인 완료 —
> [03_기술노트.md](03_기술노트.md) "2.6)").

## 14. 통계 검정

모든 주요 조건 3 seeds. paired bootstrap 또는 paired permutation test 권장. 여러
언어/태스크 비교 시 Holm correction 고려. 평균만 보고하지 말고 95% confidence
interval 또는 std 보고.

실질적 효과 기준을 사전에 설정: downstream accuracy 0.5 point 미만은 작은 차이,
performance retention 0.5% 미만은 작은 차이, PPL은 상대 변화율 기준 병기.

## 15. 성공/실패 판정 기준

**Positive result:** multilingual calibration이 2개 이상의 비영어 언어에서 일관되게
개선, macro-average 또는 worst-language retention 개선, routing/Fisher/activation
분석이 개선 원인을 일부 설명.

**Mixed result:** target-language calibration은 해당 언어에만 유리, multilingual
calibration은 평균은 개선하지만 영어 성능이 소폭 감소, 모델별 효과가 다름.

**Negative result도 논문화 가능한 형태:** calibration 언어 효과가 D²-MoE에서 매우
작음, D²-MoE의 Fisher/SVD 절차가 언어 변화에 강건함, dense PTQ에서 보고된
multilingual calibration 현상이 MoE compression에는 전이되지 않음.

중요: "효과가 없다"를 주장하려면 confidence interval과 충분한 seed가 필요하다.

## 16. 단계별 실행 계획

**Phase 0. 환경 검증** — 공식 D²-MoE 코드 실행, 원 논문의 한 모델/한 압축률 결과
재현, 압축 전후 평가 파이프라인 검증.
완료 기준: 원 논문 결과와 큰 방향이 일치, 동일 checkpoint를 반복 평가했을 때 결과가 안정적.

**Phase 1. Pilot** — 모델 1개, 압축률 60%, English/Korean/Chinese/multilingual,
seed 1개, PPL + downstream 1개, routing statistics 저장.
중단 기준: 모든 조건 차이가 거의 없고 측정 노이즈보다 작음 / 원본 모델의 KO/ZH

## 23. Disagreement-aware Calibration (제안 방법, 2026-07-25 확장 — a) 방향)

> 지금까지는 "calibration 언어가 압축 결과에 영향을 준다"는 관찰/분석
> 프로젝트였다. 이 섹션은 그 관찰에서 나온 처방 — **불일치(disagreement)
> expert에 표본을 표적 배분하는 새 calibration 전략** — 을 제안 방법으로
> 다룬다. 압축 알고리즘 자체(Fisher merge/SVD/pruning)는 바꾸지 않으므로
> §2의 "새 압축 알고리즘을 제안하지 않는다"는 원칙과 충돌하지 않는다 — 이건
> **calibration sampling 전략**의 제안이다. [04_전체요약.md](04_전체요약.md)
> "다음 단계" 5) 참고.

### 23.1 동기와 순환 문제

"언어에 따라 Fisher가 갈라지는 expert(불일치 expert)"를 찾으려면 언어별 real
Fisher를 먼저 계산해야 하는데, real Fisher는 backward pass라 비싸다(D²-MoE
비용의 주범). 언어별로 다 돌려서 불일치 expert를 찾으면, 그 사전 스캔 비용이
본 압축 비용보다 커질 수 있다 — 이게 순환 문제다.

**해법: 2-stage 설계.**
1. **Stage 1 (싸다):** Toy0/Fisher Pilot A의 forward-only proxy로 언어 간
   Fisher-proxy 불일치가 큰 expert를 저비용으로 스캔한다.
2. **Stage 2 (비싸지만 한 번만):** Stage 1에서 찾은 불일치 expert 정보로
   calibration 표본 배분을 조정한 뒤, real Fisher를 **한 번만** 계산한다.

이 설계는 지금까지 "proxy는 real Fisher의 못 미더운 대용물"이라는 한계로만
적어뒀던 것을 방법의 구성 요소로 승격시킨다 — 그리고 [04_전체요약.md](04_전체요약.md)
"다음 단계" 2.5)-1에서 어차피 측정할 proxy-real Fisher 상관이, 이 설계
("Stage 1의 proxy가 Stage 2가 노릴 expert를 정확히 짚는가")의 타당성 근거로
그대로 재사용된다. 버릴 게 없는 구조.

### 23.2 "커버한다"의 조작적 정의 — 방법의 성패가 갈리는 지점

불일치 expert에 "데이터를 더 준다"는 것의 의미는 최소 세 갈래로 해석된다:

- **(a) 표본 배분(분산 축소).** 그 expert로 라우팅되는 토큰량을 늘려 언어별
  Fisher 추정의 분산을 줄인다. **채택.**
- **(b) 언어 비중 조정(값 자체를 키움).** 그 expert를 활성화하는 언어의
  비중을 올려 Fisher 값 자체를 키운다. **기각 — 위험.** 불일치 expert는
  대개 언어 특화 expert이므로, 그 Fisher를 키우면 D²-MoE merge에서 base
  weight가 그 언어 쪽으로 끌려가 다른 언어를 해칠 수 있다. 효과의 방향이
  목적(다국어 균형)과 반대로 갈 수 있다.
- **(c) 분리 추정 후 보수적 집계.** 언어별 Fisher를 따로 추정한 뒤 불일치
  expert만 보수적으로 집계. 검토는 하되 주 정의로는 채택하지 않음.

**주 정의 (a)를 budget 최적화 문제로 정식화:** 제한된 token budget에서, 모든
언어가 합의하는 expert에는 표본을 아끼고, 불일치 expert의 언어별 Fisher가
안정적으로 추정되도록 표본을 몰아준다 — 예: **불일치 expert들의 언어별 유효
표본 수의 최솟값을 최대화**하는 배분 문제. 이 정식화가 §23.3의 위협에 대한
답도 자연스럽게 제공한다.

### 23.3 가장 중요한 위협 — "Balanced와 뭐가 다른가"

불일치 expert를 모든 언어로 "순진하게" 커버하면 결과적으로 언어를 골고루
섞는 것과 다르지 않아지고, 리뷰어는 "복잡한 절차를 거쳐 Balanced를
재발명했다"고 쓸 수 있다. **이 방법이 성립하는 유일한 조건: 동일 token
budget에서 Balanced를 이겨야 한다.**

이길 수 있는 논리: Balanced는 budget을 언어에 균등 배분하지만, 실제로 언어
간 이견이 있는 expert는 소수([04_전체요약.md](04_전체요약.md) "다음 단계"
2.5)-1에서 측정될 것)이므로, 그 소수에 budget을 표적 배분하면 같은 비용으로
worst-language 저하를 더 줄일 수 있다 — **"budget-efficient calibration"**
프레임.

**사전 등록할 성공 기준:** 동일 budget(예: 64×512)에서 제안법의
worst-language 저하 < Balanced의 worst-language 저하, 3 seeds 부호 일관.

**[2026-07-27 v3 추가] expert-balanced도 동일하게 이겨야 한다.** Balanced
(언어 균등 혼합)와는 별개 축인 expert-balanced 계열(EBSS류, expert 단위로
calibration 비중을 맞추는 기준선)도 동일 budget에서 반드시 이겨야
방법론적으로 방어 가능하다 — Must-have로 승격됨([claude_plan.md](../01_plans/claude_plan.md)
D-4). "Balanced만 이겼다"는 더 이상 충분한 검증으로 인정하지 않는다.

**추가 스트레스 테스트:** budget을 절반, 1/4로 줄인 조건에서 제안법과
Balanced의 격차가 벌어지는지 확인 — 표적 배분의 이점은 budget이 빡빡할수록
커져야 한다는 방법 자체의 논리를 검증하는 그림이 된다 (격차가 안 벌어지거나
좁아지면 방법의 핵심 논리가 틀렸다는 뜻).

### 23.4 조건부 채택 — 2×2 결과에 건다

이 방법은 Fisher 경로를 겨냥한 설계다. [04_전체요약.md](04_전체요약.md)
"다음 단계" 3) whitening 복원 → Fisher×Scale 2×2 결과에 따라 갈래를 다르게
탄다:

- **Fisher가 주범으로 나오면:** 이 방법(data-side 개입)을 기존 후보인
  **per-language 정규화 집계(aggregation-side 개입)**와 나란히 비교한다 —
  데이터 쪽 개입 vs 집계 쪽 개입의 대결 자체가 흥미로운 ablation이 된다.
- **whitening이 주범으로 나오면:** 같은 "불일치 커버" 아이디어를 scale
  추정 쪽으로 이식할 수 있는지 검토한다 — 불일치 expert의 활성화가 scale
  matrix에 충분히 반영되도록 표본을 배분. §23.2의 커버리지 목적함수(유효
  표본 수 최솟값 최대화)는 경로 중립적으로 정의되어 있어 이식 가능성이 있다.

**실행 순서:** 이 섹션 전체는 3) 2×2 실행 이후 착수 — 2×2 결과가 나오기 전엔
어느 갈래를 탈지 결정할 수 없으므로 선행 착수하지 않는다.
