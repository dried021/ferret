## 0. 문제의 재정의 (무엇이 틀렸고, 무엇은 맞았는가)

실패의 본질은 배분 "양"이 아니라 신호와 표적이 틀린 것이다. 실측이 말해주는 것:

  (a) 맞은 것: 프록시가 표적으로 고른 언어(Swahili)에 대해서는 예산↑ → 성능↑
      방향이 정확했다 (20%→50%→73%에서 19.50→17.06→15.41). 즉 "표적에 예산을
      몰아주면 그 표적은 좋아진다"는 메커니즘 자체는 작동한다.
  (b) 틀린 것 1 (신호): routing-disagreement 기반 deficiency는 "커버리지 부족"
      지표이지 "압축 취약성" 지표가 아니다. 실제 최취약 언어 Bengali가
      deficiency 5/810으로 '문제없음' 판정됨.
  (c) 틀린 것 2 (표적): cap50이 Bengali에 35%(>Balanced 20%)를 줬는데도 졌다.
      언어 비중만으론 부족하고, 그 비중이 "어느 전문가의 통계를 개선하느냐"가
      어긋나 있었다.
  (d) 새로 보이는 것 (핵심 단서): 기존 4개 조건에서 Bengali 성능이 Bengali
      자기 비중보다 **Swahili 비중과 단조 상관**한다:
          Swahili 비중   0%      20%     50%     73%
          Bengali 저하   ~17.7   22.03   22.81   31.38
      cap50에서 Bengali 비중이 늘었는데도(20→35%) 나빠진 것은 Swahili 비중이
      함께 늘었기(20→50%) 때문으로 설명 가능. KO/EN/ZH도 Swahili 비중이 큰
      조건일수록 일관되게 나빠짐 (KO: 18.71 → 20.19 → 23.30).
      → 가설: 언어 간 calibration은 독립적이지 않고 "간섭"이 있으며, 특히
        Swahili-heavy calibration이 타 언어의 whitening/Fisher 통계를 왜곡한다.

따라서 해결책은 단순히 "신호를 바꾼다"를 넘어 (1) 취약성 기반 신호, (2) 언어 간
간섭을 명시적으로 모델링한 배분, (3) 단계별(whitening 중심) 표적화의 세 층위로
설계한다. 아래 Track A/B/C가 각각 이에 대응하고, 비용이 싼 순서로 배열했다.

## 1. 선행 작업 (모든 Track의 공통 전제, 추가 GPU 비용 거의 없음)

P1. §4.1 grid 완주 — 특히 bengali_only 3 seed.
P2. 예전 단일언어 4조건(english/korean/chinese/swahili_only)의 eval_ppl.json에
    ben_Beng 키 채우기 — merge 재사용, eval만 재실행이라 매우 쌈.
P3. 새 게이트 사전등록 (재시도 전에 반드시).
    - 주 지표: mean-of-worst (3 seed), 비교군: Balanced(mixed_5lang) + 최선
      단일 언어 + (준비되면) expert-balanced.
    - 판정: 3 seed 모두 Balanced의 worst보다 낮아야 SUPPORTED (기존과 동일
      기준 유지 — 기준을 완화해서 통과시키는 모양새는 절대 금지).
    - 이번엔 cap50 같은 사후 변형을 만들지 말고, 시도할 변형을 지금 다
      등록해 둘 것.

## 2. Track A — 신호 교체: 취약성-비례 배분 (가장 싸고 확실한 1차 시도)

A1. 신호 정의 (두 후보):
    (i) Balanced 조건에서의 언어별 degradation.
    (ii) "회복 가능 갭" = Balanced degradation − own-language(100%) degradation.
        (ii)가 이론적으로 더 맞다 — 예산과 무관한 구조적 취약성 부분에는
        예산을 부어봤자 낭비이기 때문.
A2. 배분 규칙: share_l ∝ 신호_l, floor 5~10%, cap 40%.
A4. 비용: 신규 GPU = 1 조건 × 3 seed.
A5. 리스크: 언어 비중만 바꾸는 방법은 표적 전문가 문제를 못 건드릴 수 있음.

## 3. Track B — 간섭 모델링: 선형 응답 모델 + minimax 최적 배분 (본명)

B1. 모델: D_l(s) ≈ b_l + Σ_k a_{lk} · s_k (D_l = 언어 l의 bpb 증가율,
    s_k = 언어 k의 calibration 비중, Σs_k = 1). a_{·,SW}가 광범위하게
    양수인지가 검증 포인트.
B2. 학습 데이터: 8개 조건 × 3 seed × 5개 언어 관측치, 릿지 정규화 +
    leave-one-condition-out으로 적합도 확인.
B3. 최적화: min_s max_l D_l(s), s ∈ simplex, floor/cap 제약 → LP.
B4. 검증: 주 검증(게이트 동일) + 보조 검증(모델 예측력, LOO) — 이중 안전망.
B5. 비용: 신규 GPU = 1 조건 × 3 seed. 모델링/LP는 공짜.

## 4. Track C — 단계별 표적화: whitening 전용 배분 분리 (예비)

Fisher용 calibration과 whitening scale 계산용 calibration을 서로 다른 언어
구성으로 분리한다 (Fisher=Balanced, whitening=Track A/B 배분). D²-MoE
알고리즘은 불변, "각 단계가 읽는 calibration 표본의 구성"만 바뀐다.

## 5. 필수 통제 실험

R1. random-allocation control: 취약성/간섭 배분과 같은 엔트로피의 무작위
    배분 1개 × 3 seed.
R2. 기존 negative result(disagreement 기반 2변형)는 삭제하지 않고 본문에 유지.
R3. Bengali 구조적 취약성 규명 1개 (§5 메커니즘에 편입) — SVD energy 분석.

## 6. 실행 순서 및 게이트 트리

  Step 0  P1 + P2
  Step 1  P3 사전등록 (Track A/B/C 변형 전부 + 게이트 + R1까지 한 번에)
  Step 2  Track B 모델 적합 + 간섭 계수 확인 (GPU 0)
          ├ a_{·,SW} 양수 패턴 확인되면 → Track B의 s* 우선 실행
          └ 모델 적합도가 나쁘면 → Track A(ii) 우선 실행
  Step 3  선택된 1개 조건 × 3 seed 실행 → 게이트 판정
  Step 4  R1 + R3 — 승리안 확정 후 병렬

## 7. 논문 서술 원칙 (해결 성공 시)

"실패 → 원인 → 교정"의 서사로 §6을 구성. 신호의 순환성(2-stage 비용 구조)을
정직하게 밝히고, Bengali의 구조적 취약성(R3)은 배분으로 해결 안 되는 잔여분임을
명시해 주장 범위를 한정한다.
